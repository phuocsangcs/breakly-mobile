\subsection{Design Principles and Visual Language}
\label{sec:design-principles}

The user interface of Breakly is founded upon the design philosophy of \textit{Calm Computing} and \textit{Mindful Digital Well-being}. Unlike conventional media applications that leverage endless feeds, algorithmic recommendations, and variable-reward notifications to maximize user screen time, Breakly is engineered around explicit boundaries, predictable stopping points, and minimal cognitive friction. The visual design establishes a restful virtual environment where users can decompress without falling into digital consumption rabbit holes.

\subsubsection{Dual-Theme Atmosphere Architecture}
Breakly delivers two atmospheres. The colour values below are the tokens used in the code (\texttt{constants/theme.ts}), which were taken from the Figma UI kit:
\begin{itemize}[leftmargin=1.5em, itemsep=2pt]
  \item \textbf{Normal garden (light, daytime)}: warm linen background (\texttt{\#F4EDE1}), dark slate-green text (\texttt{\#1F2A2A}) and a forest-sage accent (\texttt{\#2F6B5E}). The window shows a sunny sky.
  \item \textbf{Cozy chill room (dark, night)}: deep navy background (\texttt{\#232437}), warm ivory text (\texttt{\#F6EBDD}) and a warm amber accent (\texttt{\#F2B05E}). The window shows a moon and twinkling stars.
\end{itemize}
Changing the theme swaps the room illustration, the sky and the colours, but never the position of the objects, so the user's muscle memory is kept.

\subsubsection{Typography, Elevation, and Component Tokens}
The typography uses two bundled fonts: \textit{Fraunces} (semi-bold) for the wordmark, screen titles and large numbers such as the timer, and \textit{DM Sans} (regular to bold) for body text, labels and buttons. Bundling the fonts gives the same look on iOS and Android. The hierarchy has three tiers:
\begin{itemize}[leftmargin=1.5em, itemsep=2pt]
  \item \textbf{Display and headlines} (Fraunces): screen titles, the countdown and the summary figures.
  \item \textbf{Body text} (DM Sans): article titles, track metadata, descriptions and settings rows.
  \item \textbf{Captions and metadata} (DM Sans): the timer pill, station genres, timestamps and room labels.
\end{itemize}
All interactive surfaces employ gentle elevation with soft multi-layered shadows ($Y=2\,\text{dp}$, blur $=8\,\text{dp}$, opacity $=0.08$) and generous border radii ($16\,\text{dp}$ to $24\,\text{dp}$ on surface cards; fully pill-shaped $999\,\text{dp}$ for countdown badges and action buttons).

\subsection{User Flows and Interaction Architecture}
\label{sec:user-flows}

The application interaction architecture is organized into three interlocking loops: the \textit{Onboarding Loop}, the \textit{Primary Break Loop}, and the \textit{Reflection Loop}:
\begin{enumerate}[leftmargin=1.5em, itemsep=3pt]
  \item \textbf{Onboarding \& On-Ramp Flow}: The Figma design greets first-time users with a splash screen and a 3-step carousel introducing time-boxing, the room hotspots and the automatic tear-down. In the current build the app opens directly on the Sign In screen, where the user can sign in, create an account or select \textit{Continue as guest}; the carousel is a Could item.
  \item \textbf{Primary Micro-Break Session Flow}:
    \begin{itemize}[leftmargin=1.2em, itemsep=1pt]
      \item \textit{Pre-Commitment}: From the virtual room, the user selects a strict session quota ($10$, $20$, or $30$ minutes) \textit{before} tapping any content item.
      \item \textit{Ambient Immersion}: The user taps an in-room hotspot: the \textbf{Radio} (Jamendo music), the \textbf{Newspaper} (VnExpress news in an in-app reader), the \textbf{TV} (mobile YouTube, at most 10 videos) or the \textbf{Gamepad} (daily NYT games).
      \item \textit{Media Arbitration}: Audio playback runs concurrently while the user reads articles. When the TV is turned on, background music automatically suspends to prevent competing audio streams.
      \item \textit{Non-Intrusive Countdown Warning}: At $1$ minute remaining, an ambient toast badge gently fades in, allowing the user to wind down their attention without sudden panic.
    \end{itemize}
  \item \textbf{Hard Tear-Down \& Reflection Flow}: At exactly $00:00$, all media players and WebViews are unmounted immediately. A calming \textit{Time's Up} quote transitions to a concise \textit{Break Summary} metrics card, saving the session record on the device (AsyncStorage upload queue) and on the backend.
\end{enumerate}

\subsection{Visual and Accessibility Guidelines Compliance}
\label{sec:visual-accessibility}

The screens follow the WCAG 2.1 AA targets of NFR-08. The current build implements the following measures; items not yet verified with an accessibility scanner are marked as targets.
\begin{enumerate}[leftmargin=1.5em, itemsep=3pt]
  \item \textbf{Colour contrast}: body text on the background has high contrast in both themes (\texttt{\#1F2A2A} on \texttt{\#F4EDE1}; \texttt{\#F6EBDD} on \texttt{\#232437}). The accent colours are used for buttons and highlights, and status is never shown by colour alone (the final minute also shows a toast, played games show a text mark).
  \item \textbf{Touch targets}: the room objects, labels, chips, track rows and player controls are designed for at least $44 \times 44$\,pt on iOS (to be confirmed in the accessibility test); the seek bar has a taller invisible hit area than the visible 4\,pt bar.
  \item \textbf{Screen reader semantics}: interactive elements carry accessibility roles and labels (for example ``Open music'' on the radio); the seek bar is an adjustable element that VoiceOver users can move in 15-second steps.
  \item \textbf{Motion}: the room animations (clock hands, drifting clouds, floating notes) are slow, use the native driver and never flash. Respecting the system ``Reduce Motion'' setting is a target for a later version.
  \item \textbf{Text scaling}: system font scaling is enabled; checking every screen at 130 percent text size is part of the planned accessibility test.
\end{enumerate}
