\subsection{Data Model}
\label{sec:data-model}

The backend stores its data in PostgreSQL. The schema is created by six Flyway
migrations: V1 creates the tables, V2 seeds the curated content, V3 adds the
Game Corner, V4 sets the game icons, V5 replaces The Mini with Pips and V6
adds four music stations. Applied migrations are never edited; every change is
a new version. All primary keys are UUIDs and all timestamps are stored with a
time zone. Figure~\ref{fig:erd} shows the entities and their relationships.

\subsection{Local Storage Strategy}
\label{sec:local-storage}

The app keeps on the device only what it needs to work during a break and
without a connection:
\begin{itemize}[leftmargin=1.8em,itemsep=2pt]
  \item \textbf{Secure storage} (\texttt{expo-secure-store}): the refresh
        token. The access token is kept in memory only.
  \item \textbf{AsyncStorage}: the active session (start time, planned end
        time, usage counters), the guest history, the upload queue of finished
        sessions, the preferences, the per-game local play log and the list of
        downloaded tracks.
  \item \textbf{File system} (\texttt{expo-file-system}): downloaded MP3
        files in the app's document folder, which the Files app shows on iOS.
\end{itemize}
The countdown is always derived from the stored end time rather than from
counted ticks, so it survives the app being suspended or restarted. When the
list of downloads is loaded, entries whose file no longer exists are removed.
