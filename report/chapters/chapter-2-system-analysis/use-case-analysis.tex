The use case model describes what a user can do with Breakly and which
external systems take part. It is derived from the functional requirements in
Table~\ref{tab:functional-requirements} and from the implemented application.

\paragraph{What counts as a use case.}
A use case in this model is a goal that the user starts and that produces a
visible result: a screen opens, data is created or changed, or a feature runs.
Single steps inside a goal, such as entering an email address or choosing the
session length, are written as steps of a use case rather than as use cases of
their own. Behaviour that the system performs by itself is also kept inside the
flows: the countdown, the automatic end of a session, the Session Summary
screen that follows it, background playback and the pausing of music while
videos play. Sign-in is not drawn as an \guillemotleft include\guillemotright{}
of every other use case, because Breakly can be used without an account; the
need for an account is stated in the preconditions where it applies.

\paragraph{Actors.}
\begin{itemize}[leftmargin=1.8em,itemsep=2pt,topsep=2pt]
  \item \textbf{User} -- the only primary actor. A user may work as a guest,
        whose sessions are stored on the device, or sign in so that sessions,
        streaks and preferences are saved to their account and available on
        any device.
  \item \textbf{Jamendo} \guillemotleft system\guillemotright{} -- the music
        catalogue. The Breakly backend requests Creative Commons tracks by
        tag, and the app streams or downloads the MP3 files.
  \item \textbf{VnExpress RSS} \guillemotleft system\guillemotright{} -- the
        news feeds aggregated by the backend, and the publisher website that
        shows each full article.
  \item \textbf{YouTube} \guillemotleft system\guillemotright{} -- the mobile
        YouTube website shown inside the app for the video service.
  \item \textbf{NYT Games} \guillemotleft system\guillemotright{} -- the daily
        puzzle games of The New York Times (Wordle, Connections, Strands and
        Pips), played in an in-app browser.
\end{itemize}
The Breakly backend (Spring Boot and PostgreSQL) is part of the system under
design, so it is inside the system boundary and is not an actor.

\subsection{Use Case Descriptions}
\label{sec:usecase-descriptions}

Each use case is specified with the same template. Steps are numbered in the
normal flow; alternative flows (A) and exception flows (E) name the step at
which they branch.

% ---------------------------------------------------------------------
\subsubsection{Account}

% ---------------------------- UC-01 ----------------------------------
\begin{ucspec}{UC-01: Sign up}{tab:uc-01}
\ucrow{Use Case ID}{UC-01}
\ucrow{Primary Actor}{User}
\ucrow{Secondary Actor}{--}
\ucrow{Description}{A user creates a Breakly account so that sessions, streaks and preferences are saved to the account instead of only on the device.}
\ucrow{Related FR}{FR 1.1, FR 1.4}
\ucrow{Priority}{Must}
\ucrow{Preconditions}{The user is not signed in (first launch or guest mode).}
\ucrow{Trigger}{The user selects \textit{Create account} on the Sign In screen, or \textit{Sign in / Create account} in Settings.}
\ucrow{Normal Flow}{%
1. The system shows the Sign Up form with display name, email and password fields.\newline
2. The user enters a display name, an email address and a password of at least 8 characters.\newline
3. The user submits the form.\newline
4. The system checks that the email has a valid format and that the password has at least 8 characters.\newline
5. The system sends the registration request to the Breakly backend, which stores the password as a BCrypt hash and returns an access token and a refresh token.\newline
6. The system stores the refresh token in secure device storage (NFR-04).\newline
7. The system uploads any sessions recorded on the device in guest mode and loads the account preferences.\newline
8. The system shows the Home Space.}
\ucrow{Alternative Flows}{%
A1. The user already has an account: at step 1 the user selects \textit{Sign in} and continues with UC-02.\newline
A2. The user selects \textit{Continue as guest}: the system shows the Home Space in guest mode and the use case ends without an account.}
\ucrow{Exception Flows}{%
E1. Invalid email or a password shorter than 8 characters: at step 4 the system shows an error next to the field and does not send the request.\newline
E2. Email already registered: at step 5 the backend answers \texttt{409 EMAIL\_ALREADY\_EXISTS}; the system shows an error message and no second account is created.\newline
E3. No connection or the backend is unavailable: the system shows an error message; no account is created and the user can try again.}
\ucrow{Postconditions}{%
Success: the account exists, the user is signed in, and guest sessions are attached to the account.\newline
Failure: no account is created and the user stays on the Sign Up form.}
\end{ucspec}

% ---------------------------- UC-02 ----------------------------------
\begin{ucspec}{UC-02: Sign in}{tab:uc-02}
\ucrow{Use Case ID}{UC-02}
\ucrow{Primary Actor}{User}
\ucrow{Secondary Actor}{--}
\ucrow{Description}{A registered user signs in with email and password and stays signed in until signing out.}
\ucrow{Related FR}{FR 1.2, FR 1.4}
\ucrow{Priority}{Must}
\ucrow{Preconditions}{The user has an account and is not signed in on this device.}
\ucrow{Trigger}{The user opens the Sign In screen from the first screen of the app or from Settings.}
\ucrow{Normal Flow}{%
1. The system shows the Sign In form with email and password fields.\newline
2. The user enters the registered email and password and submits the form.\newline
3. The system checks that both fields are filled in and sends the credentials to the Breakly backend.\newline
4. The backend verifies the password and returns a short-lived access token (15 minutes) and a refresh token (30 days).\newline
5. The system stores the refresh token in secure device storage.\newline
6. The system uploads sessions queued on the device and loads the account preferences (theme, default duration, one-minute notice, radio volume).\newline
7. The system shows the Home Space with the saved theme.}
\ucrow{Alternative Flows}{%
A1. Saved sign-in: when the app starts and a refresh token is stored, the system obtains a new access token in the background and shows the Home Space without the form.\newline
A2. The user has no account: the user selects \textit{Create account} and continues with UC-01.\newline
A3. The user selects \textit{Forgot password?}: the system explains that password reset is not available in this version (it is listed as a Could item).}
\ucrow{Exception Flows}{%
E1. Empty field: at step 3 the system highlights the field and does not send the request.\newline
E2. Wrong email or password: at step 4 the backend answers \texttt{401 INVALID\_CREDENTIALS}; the system shows an error and the user stays on the form.\newline
E3. No connection: the system shows an error message and the user can try again.\newline
E4. Expired or revoked refresh token at start-up (A1): the backend rejects the refresh request; the system deletes the stored token and continues in guest mode.}
\ucrow{Postconditions}{%
Success: the user is signed in and stays signed in after the app is restarted.\newline
Failure: the user stays signed out.}
\end{ucspec}

% ---------------------------- UC-03 ----------------------------------
\begin{ucspec}{UC-03: Sign out}{tab:uc-03}
\ucrow{Use Case ID}{UC-03}
\ucrow{Primary Actor}{User}
\ucrow{Secondary Actor}{--}
\ucrow{Description}{A signed-in user signs out so that the account can no longer be used from this device.}
\ucrow{Related FR}{FR 1.3}
\ucrow{Priority}{Must}
\ucrow{Preconditions}{The user is signed in.}
\ucrow{Trigger}{The user selects \textit{Sign out} in the Account group of Settings.}
\ucrow{Normal Flow}{%
1. The user selects \textit{Sign out}.\newline
2. The system sends the refresh token to the backend, which revokes it.\newline
3. The system deletes the tokens from secure device storage.\newline
4. The system switches to guest mode; Settings now shows \textit{Sign in / Create account} instead of the account details.}
\ucrow{Alternative Flows}{%
A1. A break session is active: the session keeps running in guest mode; its record is stored on the device when it ends.}
\ucrow{Exception Flows}{%
E1. No connection at step 2: the system still deletes the stored tokens and switches to guest mode; signing out on the device never depends on the network.}
\ucrow{Postconditions}{%
No token is stored on the device, the refresh token is revoked on the server when it could be reached, and the account history is no longer loaded.}
\end{ucspec}

\subsubsection{Break Session}

% ---------------------------- UC-04 ----------------------------------
\begin{ucspec}{UC-04: Start a break session}{tab:uc-04}
\ucrow{Use Case ID}{UC-04}
\ucrow{Primary Actor}{User}
\ucrow{Secondary Actor}{--}
\ucrow{Description}{The user starts a time-boxed break by tapping an object in the Space. The system runs the countdown, warns when one minute is left, ends the break automatically and shows the Session Summary.}
\ucrow{Related FR}{FR 2.1--2.6, FR 3.1, FR 7.1, FR 7.2}
\ucrow{Priority}{Must}
\ucrow{Preconditions}{The Home Space is displayed and no session is active.}
\ucrow{Trigger}{The user taps the radio, the newspaper, the TV or the gamepad in the Space.}
\ucrow{Normal Flow}{%
1. The system shows the Home Space with the four labelled objects and the duration selector (10, 20 or 30 minutes), preset to the default duration from Settings.\newline
2. The user taps an object.\newline
3. The system creates a session with a client-generated ID, stores the start time and the planned end time on the device, and starts the countdown.\newline
4. The system opens the matching service: Radio (UC-07), News (UC-09), TV (UC-11) or Game Corner (UC-12).\newline
5. The system shows the remaining time (mm:ss) on every screen and recalculates it every second from the stored end time.\newline
6. When 60 seconds remain, the system shows a ``One minute left'' toast for about four seconds and highlights the timer.\newline
7. When the countdown reaches 00:00, the system stops music and video, closes the content screens and marks the session as completed.\newline
8. The system shows the Session Summary: time used, music listening time, articles opened, videos watched, games played and the updated streak.\newline
9. The system saves the session record on the device and uploads it to the backend.\newline
10. The user selects \textit{Back to room} and the Home Space is shown.}
\ucrow{Alternative Flows}{%
A1. Choose another duration: at step 1 the user selects 10, 20 or 30 minutes before tapping an object; exactly one option is selected.\newline
A2. A session is already active: tapping an object opens its service and the countdown continues without restarting.\newline
A3. The app is in the background or the device is locked: the countdown stays correct because it is computed from the end time; if the time runs out meanwhile, the summary is shown when the app returns to the foreground.\newline
A4. One-minute notice turned off in Settings: step 6 shows no toast.\newline
A5. The user ends the break before 00:00: the flow continues in UC-05.}
\ucrow{Exception Flows}{%
E1. No connection at step 9: the record stays in the upload queue on the device and is sent automatically later (the server ignores duplicates by client ID).\newline
E2. The content of the opened service cannot be loaded: the service shows its error state with a retry option while the countdown keeps running.}
\ucrow{Postconditions}{%
The session has ended, playback has stopped, the summary has been shown, and the record is stored on the device and, when online and signed in, on the server.}
\end{ucspec}

% ---------------------------- UC-05 ----------------------------------
\begin{ucspec}{UC-05: End session early}{tab:uc-05}
\ucrow{Use Case ID}{UC-05}
\ucrow{Primary Actor}{User}
\ucrow{Secondary Actor}{--}
\ucrow{Description}{The user stops an active break before the countdown reaches zero, after confirming.}
\ucrow{Related FR}{FR 2.7, FR 7.1, FR 7.2}
\ucrow{Priority}{Should}
\ucrow{Preconditions}{A session is active.}
\ucrow{Trigger}{The user selects \textit{End break} on the Home Space or from the session timer on a content screen.}
\ucrow{Normal Flow}{%
1. The system asks ``End break early?'' and explains that the progress so far will be saved.\newline
2. The user selects \textit{End break}.\newline
3. The system stops music and video and stops the countdown.\newline
4. The system records the session with the time actually used and the end reason \textit{ended early}.\newline
5. The system shows the Session Summary for this session.\newline
6. The system saves the record on the device and uploads it to the backend.}
\ucrow{Alternative Flows}{%
A1. The user selects \textit{Cancel} at step 2: the dialog closes and the session continues unchanged.\newline
A2. The countdown reaches zero while the dialog is open: the session ends automatically as in UC-04.}
\ucrow{Exception Flows}{%
E1. No connection at step 6: the record stays in the upload queue and is sent when the connection returns.}
\ucrow{Postconditions}{%
Confirmed: the session has ended with the reason \textit{ended early} and its record is saved.\newline
Cancelled: the session and its countdown are unchanged.}
\end{ucspec}

\subsubsection{Space and Themes}

% ---------------------------- UC-06 ----------------------------------
\begin{ucspec}{UC-06: Change theme}{tab:uc-06}
\ucrow{Use Case ID}{UC-06}
\ucrow{Primary Actor}{User}
\ucrow{Secondary Actor}{--}
\ucrow{Description}{The user switches the Space between the Cozy chill room (night) and Normal garden (day) themes, and the choice is remembered.}
\ucrow{Related FR}{FR 3.2, FR 3.3}
\ucrow{Priority}{Must}
\ucrow{Preconditions}{--}
\ucrow{Trigger}{The user opens the Theme Selector from Settings (\textit{Room theme}) or taps the theme switch in the Home Space header.}
\ucrow{Normal Flow}{%
1. The system shows both themes with a preview and a name and marks the current one.\newline
2. The user selects a theme and applies it.\newline
3. The system changes the room illustration, the window sky (moon and stars at night, sun by day) and the interface colours; the positions of the objects stay the same.\newline
4. The system saves the theme on the device and, when signed in, in the account preferences.}
\ucrow{Alternative Flows}{%
A1. Quick switch: the theme switch in the Home Space header toggles between the two themes directly (steps 1--2 are skipped).\newline
A2. The user leaves the selector without applying: the current theme is kept.\newline
A3. First launch: the Cozy chill room theme is used by default.}
\ucrow{Exception Flows}{%
E1. The preference cannot be saved to the server: the theme stays applied on the device and is sent with the next preference update.}
\ucrow{Postconditions}{%
The selected theme is shown and is used again after the app is restarted.}
\end{ucspec}

\subsubsection{Music}

% ---------------------------- UC-07 ----------------------------------
\begin{ucspec}{UC-07: Listen to radio}{tab:uc-07}
\ucrow{Use Case ID}{UC-07}
\ucrow{Primary Actor}{User}
\ucrow{Secondary Actor}{Jamendo}
\ucrow{Description}{The user picks a station and controls playback. Music keeps playing on other screens and with the device locked, and pauses while the TV is open.}
\ucrow{Related FR}{FR 4.1--4.5, FR 4.7, FR 7.7, FR 7.8}
\ucrow{Priority}{Must}
\ucrow{Preconditions}{A session is active (started from the radio in UC-04 or already running).}
\ucrow{Trigger}{The user taps the radio in the Space.}
\ucrow{Normal Flow}{%
1. The system shows the Radio screen with the stations Lo-fi, Piano, Acoustic, Nature, Jazz, Chill, Classical and Guitar.\newline
2. The user selects a station.\newline
3. The system asks the backend for the station's tracks; the backend fetches them from Jamendo by tag and caches the list for 10 minutes.\newline
4. The system starts the first track and shows its title, artist, artwork, Creative Commons licence and a seek bar.\newline
5. The user controls playback: play or pause, previous or next track, drag the seek bar, or change the volume.\newline
6. When the user opens another screen, playback continues and a mini-player with play/pause is shown on the Home Space, News, Game Corner and History screens.\newline
7. When the device is locked, playback continues and the lock screen shows the track with play/pause and 15-second seek controls.\newline
8. When the session ends, the system stops playback and removes the lock-screen controls.}
\ucrow{Alternative Flows}{%
A1. The user selects another station: the system loads that station and plays its first track.\newline
A2. The user opens the TV while music plays: the music pauses and resumes when the user leaves the TV, unless the user had paused it before.\newline
A3. Download a track: the user selects the download control of a track and continues with UC-08.\newline
A4. Offline station: when tracks have been downloaded, the station \textit{Downloaded} plays them from the device without a connection.\newline
A5. The user taps the licence credit: the licence page opens in the browser.}
\ucrow{Exception Flows}{%
E1. A track cannot be played: the system skips to the next track; if every track of the station fails, playback stops and a message asks the user to check the connection.\newline
E2. Jamendo is unavailable or returns no tracks: the backend serves the last cached list or a small set of demo tracks, so the station still plays.\newline
E3. No connection to the backend: the system shows an error message with a retry option; the countdown keeps running.}
\ucrow{Postconditions}{%
Playback reflects the user's last action, and the listening time is counted for the Session Summary.}
\end{ucspec}

% ---------------------------- UC-08 ----------------------------------
\begin{ucspec}{UC-08: Download track (MP3)}{tab:uc-08}
\ucrow{Use Case ID}{UC-08}
\ucrow{Primary Actor}{User}
\ucrow{Secondary Actor}{Jamendo}
\ucrow{Description}{The user saves a track as an MP3 file for offline listening and can also save the file to the phone.}
\ucrow{Related FR}{FR 4.6}
\ucrow{Priority}{Should}
\ucrow{Preconditions}{The Radio screen is open (UC-07) and the artist allows downloads of the track (the track has a download link).}
\ucrow{Extension point}{Track list and full player of UC-07.}
\ucrow{Trigger}{The user taps the download icon of a track or \textit{Download MP3} in the full player.}
\ucrow{Normal Flow}{%
1. The system shows a progress indicator on the track.\newline
2. The system downloads the MP3 file from Jamendo into the app's storage.\newline
3. The system marks the track as downloaded and adds it to the \textit{Downloaded} station.\newline
4. The user can now play the track without a connection.}
\ucrow{Alternative Flows}{%
A1. Save to phone: the user taps a downloaded track and selects \textit{Save to phone}; on iOS the share sheet opens so that the file can be saved to the Files app, and on Android the user picks a folder.\newline
A2. Remove download: the user selects \textit{Remove download}; the file is deleted and the track leaves the \textit{Downloaded} station.\newline
A3. The track has no download link: no download control is shown for it.}
\ucrow{Exception Flows}{%
E1. The download fails: the icon shows an error state and the user can retry.\newline
E2. The file of a downloaded track has been removed by the system: the entry is dropped when the downloads are loaded again.}
\ucrow{Postconditions}{%
The MP3 file is stored on the device and listed in the \textit{Downloaded} station.}
\end{ucspec}

\subsubsection{News}

% ---------------------------- UC-09 ----------------------------------
\begin{ucspec}{UC-09: Read news}{tab:uc-09}
\ucrow{Use Case ID}{UC-09}
\ucrow{Primary Actor}{User}
\ucrow{Secondary Actor}{VnExpress RSS}
\ucrow{Description}{The user browses the latest articles, optionally filters or refreshes the list, and reads an article inside the app.}
\ucrow{Related FR}{FR 5.1--5.4, FR 7.7, FR 7.8}
\ucrow{Priority}{Must}
\ucrow{Preconditions}{A session is active.}
\ucrow{Trigger}{The user taps the newspaper in the Space.}
\ucrow{Normal Flow}{%
1. The system shows placeholder cards while the backend loads the VnExpress RSS feeds (cached for 5 minutes).\newline
2. The system lists the articles from newest to oldest; each card shows the title, source, publication time and an image when the feed has one.\newline
3. The user taps an article.\newline
4. The system opens the article page in an in-app reader with a loading bar, the source domain and the session timer.\newline
5. The user reads the article and goes back to the list.}
\ucrow{Alternative Flows}{%
A1. Filter by category: at step 2 the user selects a category chip; only articles of that feed are listed, and \textit{All} restores the full list.\newline
A2. Refresh: at step 2 the user pulls the list down; the feeds are reloaded.\newline
A3. The page cannot be shown in the reader: the flow continues in UC-10.}
\ucrow{Exception Flows}{%
E1. No connection on the first load: the system shows an error message with a retry option; the countdown keeps running.\newline
E2. The selected category has no articles: an empty-state message is shown.}
\ucrow{Postconditions}{%
Each opened article is counted for the Session Summary. No server data is changed.}
\end{ucspec}

% ---------------------------- UC-10 ----------------------------------
\begin{ucspec}{UC-10: Open full article}{tab:uc-10}
\ucrow{Use Case ID}{UC-10}
\ucrow{Primary Actor}{User}
\ucrow{Secondary Actor}{VnExpress RSS (publisher website)}
\ucrow{Description}{When an article cannot be displayed in the in-app reader, the user opens the full article on the publisher website in the system browser.}
\ucrow{Related FR}{FR 5.5}
\ucrow{Priority}{Should}
\ucrow{Preconditions}{The article reader of UC-09 has failed to load the page.}
\ucrow{Extension point}{Article reader of UC-09, after a loading failure.}
\ucrow{Trigger}{The reader shows its failure message with \textit{Try again}, \textit{Open in browser} and \textit{Back to News}.}
\ucrow{Normal Flow}{%
1. The user selects \textit{Open in browser}.\newline
2. The system opens the article URL in the system browser view.\newline
3. The user reads the article and closes the browser view.\newline
4. The system shows the Breakly reader again; the countdown has kept running.}
\ucrow{Alternative Flows}{%
A1. The user selects \textit{Try again}: the reader reloads the page and UC-09 continues.\newline
A2. The user selects \textit{Back to News}: the article list is shown.}
\ucrow{Exception Flows}{%
E1. The browser view cannot be opened: the system shows an error message under the buttons.}
\ucrow{Postconditions}{%
The user is back in Breakly and the session countdown is unaffected.}
\end{ucspec}

\subsubsection{Videos}

% ---------------------------- UC-11 ----------------------------------
\begin{ucspec}{UC-11: Watch videos}{tab:uc-11}
\ucrow{Use Case ID}{UC-11}
\ucrow{Primary Actor}{User}
\ucrow{Secondary Actor}{YouTube}
\ucrow{Description}{The user browses the real mobile YouTube website inside the app and watches up to ten videos in one break; the TV then shows an end card instead of more videos.}
\ucrow{Related FR}{FR 6.1--6.3, FR 4.5}
\ucrow{Priority}{Should}
\ucrow{Preconditions}{A session is active.}
\ucrow{Trigger}{The user taps the TV in the Space.}
\ucrow{Normal Flow}{%
1. The system pauses the music if it is playing.\newline
2. The system opens \texttt{m.youtube.com} in an in-app browser under a header with the domain, a loading bar and the session timer.\newline
3. The user searches or browses YouTube and opens a video.\newline
4. The system counts each distinct video the user opens and shows ``Video $n$ of 10'' with a progress bar.\newline
5. After the tenth video, the system closes the browser and shows an end card with a short message and \textit{Return to Home Space}.\newline
6. The user returns to the Home Space; the music resumes if it was playing before.}
\ucrow{Alternative Flows}{%
A1. A link leads outside YouTube: it opens in the system browser instead of the TV; links that would switch to another app are blocked.\newline
A2. The user leaves the TV before the limit: video playback stops; when the TV is opened again in the same session, the count continues.\newline
A3. The app goes to the background: video playback is paused.\newline
A4. The break ends while the TV is open: the browser is closed and the end card says that the break is over.}
\ucrow{Exception Flows}{%
E1. YouTube cannot be loaded: the loading bar stops and the in-app browser shows the loading error; the countdown keeps running and the user can go back.}
\ucrow{Postconditions}{%
At most ten videos have been opened in this session, no video plays after the end card, and the number of videos watched is counted for the Session Summary.}
\end{ucspec}

\subsubsection{Game Corner}

% ---------------------------- UC-12 ----------------------------------
\begin{ucspec}{UC-12: Play daily game}{tab:uc-12}
\ucrow{Use Case ID}{UC-12}
\ucrow{Primary Actor}{User}
\ucrow{Secondary Actor}{NYT Games}
\ucrow{Description}{The user plays one of the free daily puzzles of The New York Times (Wordle, Connections, Strands, Pips) inside the app; the play is recorded once per day.}
\ucrow{Related FR}{FR 8.1--8.3}
\ucrow{Priority}{Should}
\ucrow{Preconditions}{A session is active.}
\ucrow{Trigger}{The user taps the gamepad in the Space.}
\ucrow{Normal Flow}{%
1. The system shows the Game Corner with the four games; each row shows the game icon, a short description, whether it was played today and the user's streak for that game.\newline
2. The user selects a game.\newline
3. The system opens the game page in an in-app browser under a header with the domain and the session timer.\newline
4. When the page has loaded for the first time today, the system records the play with the user's local date; the backend stores at most one play per user, game and day.\newline
5. The user plays and goes back to the Game Corner, where the game is marked as played today.}
\ucrow{Alternative Flows}{%
A1. Guest mode: the play is recorded only on the device and the streak is calculated locally.\newline
A2. The game was already played today: it can be opened again, but no second play is recorded.\newline
A3. A link leads outside the game site: it opens in the system browser.}
\ucrow{Exception Flows}{%
E1. The game page cannot be loaded: the system shows an error state with a retry option; no play is recorded.\newline
E2. The play cannot be sent to the backend: the local record keeps the game marked as played today.}
\ucrow{Postconditions}{%
The game is marked as played today, the per-game streak is updated, and the game is counted in the Session Summary.}
\end{ucspec}

\subsubsection{Progress and Settings}

% ---------------------------- UC-13 ----------------------------------
\begin{ucspec}{UC-13: View history and streak}{tab:uc-13}
\ucrow{Use Case ID}{UC-13}
\ucrow{Primary Actor}{User}
\ucrow{Secondary Actor}{--}
\ucrow{Description}{The user reviews past breaks and the current streak of consecutive days with a break.}
\ucrow{Related FR}{FR 7.3, FR 7.4}
\ucrow{Priority}{Must}
\ucrow{Preconditions}{--}
\ucrow{Trigger}{The user selects \textit{History} in the bottom bar.}
\ucrow{Normal Flow}{%
1. The system loads the session history from the backend (20 records per page) and the statistics: current streak, longest streak, total breaks and total minutes.\newline
2. The system shows the statistics and lists the sessions grouped by day from newest to oldest; each row shows the duration, the start and end time and the services used, or \textit{ended early} when no service was opened.\newline
3. The user scrolls through the history and leaves the screen.}
\ucrow{Alternative Flows}{%
A1. Guest mode: the history and the streak are calculated from the sessions stored on the device.\newline
A2. No sessions yet: the system shows an empty-state message and a streak of zero.}
\ucrow{Exception Flows}{%
E1. The history cannot be loaded from the backend: the system shows an error message with a retry option.}
\ucrow{Postconditions}{%
No data is changed; the user has seen the history and the current streak.}
\end{ucspec}

% ---------------------------- UC-14 ----------------------------------
\begin{ucspec}{UC-14: Manage settings}{tab:uc-14}
\ucrow{Use Case ID}{UC-14}
\ucrow{Primary Actor}{User}
\ucrow{Secondary Actor}{--}
\ucrow{Description}{The user adjusts the break settings and views the content credits on the Profile and Settings screen.}
\ucrow{Related FR}{FR 7.5, FR 7.6}
\ucrow{Priority}{Should}
\ucrow{Preconditions}{--}
\ucrow{Trigger}{The user selects \textit{Profile} in the bottom bar.}
\ucrow{Normal Flow}{%
1. The system shows the profile card (name, email, number of breaks, streak and total time), the break settings and the content credits.\newline
2. The user changes a setting: the default break length (10, 20 or 30 minutes), the one-minute warning (on or off) or the radio volume (40 to 100 percent).\newline
3. The system applies the new value at once and saves it on the device and, when signed in, in the account preferences.}
\ucrow{Alternative Flows}{%
A1. The user selects \textit{Room theme}: the flow continues in UC-06.\newline
A2. A setting is changed during a session: the new value applies to the rest of that session.\newline
A3. The user selects \textit{Sign out} (UC-03) or, in guest mode, \textit{Sign in / Create account} (UC-02).}
\ucrow{Exception Flows}{%
E1. The preferences cannot be saved to the server: the value is kept on the device and sent with the next update.}
\ucrow{Postconditions}{%
The settings are kept after the app is restarted.}
\end{ucspec}
