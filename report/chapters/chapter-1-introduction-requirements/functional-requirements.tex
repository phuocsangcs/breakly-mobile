The functional requirements of Breakly specify the concrete system behaviours
and user interactions that the application must support. They are organised
into seven functional modules and traced to the User Requirements
(UR-01 to UR-20), and every user requirement is covered by at least one
functional requirement. The catalogue contains 34 Functional Requirements,
20 with Must priority and 14 with Should priority. Each requirement is
accompanied by acceptance criteria that can be turned directly into test
cases.

\multicolumn{5}{|c|}{\textbf{Module 1 --- Authentication \& Account Management}} \\ \hline

\frfirst{FR 1.1}
  {The system shall allow a new user to create an account with an email address and a password.}
  {UR-01}
  {Given a valid, unused email and a password of at least 8 characters, when the user submits the sign-up form, then the account is created and the user is signed in.}
  {Must}
\acnext{Given an email that is already registered, when the user submits the form, then an error message is shown and no second account is created.}
\acend{Given an invalid email format or a password shorter than 8 characters, then an inline error is shown and the form is not submitted.}

\frfirst{FR 1.2}
  {The system shall allow a registered user to sign in with email and password and remain signed in until the user signs out.}
  {UR-01}
  {Given valid credentials, when the user submits the sign-in form, then the Home Space is shown.}
  {Must}
\acnext{Given incorrect credentials, then an error message is shown and the user stays on the sign-in screen.}
\acend{Given a signed-in user, when the app is closed and reopened, then the user is still signed in.}

\frfirst{FR 1.3}
  {The system shall allow a signed-in user to sign out.}
  {UR-01}
  {When the user selects Sign out in Settings, then the Sign In screen is shown and the stored sign-in credentials are removed from the device.}
  {Must}
\acend{After signing out, the previous account's session history is no longer visible on the device.}

\multicolumn{5}{|c|}{\textbf{Module 2 --- Session Management}} \\ \hline

\frfirst{FR 2.1}
  {The system shall allow the user to choose a session duration of 10, 20 or 30 minutes.}
  {UR-02}
  {The Home Space shows three duration options (10, 20 and 30 minutes), with 20 minutes selected by default.}
  {Must}
\acnext{Exactly one option is selected at a time, and selecting another option changes the selection.}
\acend{While a session is active, the duration cannot be changed.}

\frfirst{FR 2.2}
  {The system shall start a session when the user taps the radio, the newspaper or the TV in the Space while no session is active.}
  {UR-03}
  {Given no active session, when the user taps an object, then the countdown starts from the selected duration and the matching service screen opens.}
  {Must}
\acnext{A session can be started in at most two taps from the Home Space (duration, then object).}
\acend{Given an active session, when the user taps another object, then that service opens and the countdown continues without restarting.}

\frfirst{FR 2.3}
  {The system shall display the remaining session time on every screen while a session is active.}
  {UR-04}
  {The remaining time is visible on the Home Space, Radio, News, Article and TV screens during a session.}
  {Must}
\acend{The displayed time updates every second in minutes and seconds.}

\frfirst{FR 2.4}
  {The system shall keep the countdown accurate when the app is in the background or the device is locked.}
  {UR-04}
  {Given a 10-minute session, when the app is in the background for 3 minutes and then reopened, then the remaining time is 7 minutes $\pm$ 2 seconds.}
  {Must}
\acend{Given the countdown reaches zero while the app is in the background, when the app is reopened, then the session is shown as ended and its summary is available.}

\frfirst{FR 2.5}
  {The system shall show a gentle notice when one minute of the session remains.}
  {UR-05}
  {When 60 seconds remain, a non-blocking message ``One minute left'' appears for at least 3 seconds.}
  {Must}
\acnext{The session timer is visually highlighted during the final minute.}
\acend{Given the one-minute notice is turned off in Settings, then no message is shown.}

\frfirst{FR 2.6}
  {The system shall end the session automatically when the countdown reaches zero.}
  {UR-05}
  {When the countdown reaches zero, then music and video playback stop.}
  {Must}
\acnext{The Session Summary screen is shown.}
\acend{The session record is saved with its start time and duration.}

\frfirst{FR 2.7}
  {The system shall allow the user to end an active session early after confirmation.}
  {UR-06}
  {When the user selects End session, then a confirmation dialog is shown.}
  {Should}
\acnext{When the user confirms, then the session ends and the Session Summary screen is shown.}
\acend{When the user cancels, then the session continues unchanged.}

\multicolumn{5}{|c|}{\textbf{Module 3 --- Space and Themes}} \\ \hline

\frfirst{FR 3.1}
  {The system shall present the Home Space as a full-screen illustrated scene in which the radio, the newspaper and the TV open the music, news and short-video services.}
  {UR-07}
  {The radio, newspaper and TV are each tappable and carry a visible label (Music, News, Short Videos).}
  {Must}
\acnext{Each tappable object has a touch target of at least 48 dp.}
\acend{The duration selector and, during a session, the timer are shown on top of the scene with readable contrast.}

\frfirst{FR 3.2}
  {The system shall provide two themes, Cozy Room and Garden, that the user can select in the Theme Selector.}
  {UR-08}
  {The Theme Selector lists both themes with a preview image and a name.}
  {Must}
\acnext{When the user applies a theme, then the Home Space background and colours change while the layout and object positions stay the same.}
\acend{If a theme image cannot be loaded, then a fallback background in the theme colours is shown and the objects remain usable.}

\frfirst{FR 3.3}
  {The system shall remember the selected theme.}
  {UR-08}
  {On the first launch, the Cozy Room theme is shown by default.}
  {Must}
\acend{After the app is closed and reopened, the last selected theme is shown.}

\multicolumn{5}{|c|}{\textbf{Module 4 --- Music (Radio)}} \\ \hline

\frfirst{FR 4.1}
  {The system shall allow the user to choose a music station category and start playback.}
  {UR-09}
  {The Radio screen lists the available categories (for example Lo-fi, Piano, Acoustic and Nature).}
  {Must}
\acnext{When the user selects a category, a track from that category starts playing.}
\acend{Only one category is selected at a time.}

\frfirst{FR 4.2}
  {The system shall provide play, pause, next-track and volume controls.}
  {UR-09}
  {Pause stops the audio and the control changes to play; play resumes from the same position.}
  {Must}
\acnext{Next track starts another track from the selected category.}
\acend{The volume control changes the playback volume.}

\frfirst{FR 4.3}
  {The system shall show the title, artist and artwork of the current track on the Radio screen, and a mini-player on other screens while music plays.}
  {UR-09}
  {The Radio screen shows the title, artist and artwork of the current track.}
  {Should}
\acend{While music plays, a mini-player with a play/pause control is shown on the News and Article screens.}

\frfirst{FR 4.4}
  {The system shall keep music playing when the user moves between screens or locks the device.}
  {UR-10}
  {Moving from the Radio screen to another screen does not interrupt playback.}
  {Must}
\acnext{Locking the device during a session does not stop playback.}
\acend{Playback stops when the session ends.}

\frfirst{FR 4.5}
  {The system shall pause music while the TV is open and resume it afterwards.}
  {UR-10}
  {When the TV opens while music is playing, the music pauses.}
  {Should}
\acnext{When the user leaves the TV, the music resumes from the paused position.}
\acend{If the user had paused the music manually, it stays paused after leaving the TV.}

\multicolumn{5}{|c|}{\textbf{Module 5 --- News}} \\ \hline

\frfirst{FR 5.1}
  {The system shall display a list of the latest articles from the configured news feeds.}
  {UR-11}
  {Each article card shows the title, source and publication time, and an image when the feed provides one.}
  {Must}
\acnext{Articles are listed from newest to oldest.}
\acend{While articles are loading, placeholder cards are shown.}

\frfirst{FR 5.2}
  {The system shall allow the user to filter articles by category.}
  {UR-11}
  {Category chips are shown above the article list.}
  {Should}
\acnext{When the user selects a category, only articles from that category are listed.}
\acend{Selecting the all-articles chip restores the full list.}

\frfirst{FR 5.3}
  {The system shall allow the user to refresh the article list.}
  {UR-11}
  {When the user pulls the list down, then the feeds are reloaded and newer articles appear at the top.}
  {Should}
\acend{If the refresh fails, then an error message is shown and the existing list is kept.}

\frfirst{FR 5.4}
  {The system shall allow the user to read an article inside the app.}
  {UR-12}
  {When the user taps an article card, then the Article screen opens inside the app.}
  {Must}
\acnext{The Article screen shows the title, source, publication time, image (if available) and the content provided by the feed.}
\acend{The session countdown remains visible while reading.}

\frfirst{FR 5.5}
  {The system shall allow the user to open the full article on the source website.}
  {UR-13}
  {The Article screen offers a ``Read full article'' action.}
  {Should}
\acnext{When the user selects it, then the source page opens in a browser view.}
\acend{When the user returns, the Article screen is shown and the countdown has kept running.}

\multicolumn{5}{|c|}{\textbf{Module 6 --- Short Videos (TV)}} \\ \hline

\frfirst{FR 6.1}
  {The system shall show short videos in a full-screen vertical feed.}
  {UR-14}
  {When the user opens the TV, the first clip starts playing in full screen.}
  {Should}
\acnext{A swipe up moves to the next clip and a swipe down moves to the previous clip.}
\acend{A progress indicator shows the position of the current clip in the feed.}

\frfirst{FR 6.2}
  {The system shall allow the user to pause, resume, mute and unmute a video.}
  {UR-14}
  {Tapping the video toggles between pause and play.}
  {Should}
\acend{The mute control switches the sound off and on.}

\frfirst{FR 6.3}
  {The system shall limit each video feed to a fixed number of clips and finish it with an end card.}
  {UR-15}
  {A feed contains at most 10 clips.}
  {Should}
\acnext{After the last clip, an end card with a closing message is shown instead of further videos.}
\acnext{No further clip plays automatically after the end card appears.}
\acend{The user can return to the Home Space from the end card.}

\multicolumn{5}{|c|}{\textbf{Module 7 --- Progress, Settings and Reliability}} \\ \hline

\frfirst{FR 7.1}
  {The system shall show a summary when a session ends.}
  {UR-16}
  {When a session ends, the Session Summary screen shows the total time used.}
  {Should}
\acnext{The summary shows the time spent listening to music, the number of articles opened and the number of videos watched.}
\acend{The Done button returns the user to the Home Space.}

\frfirst{FR 7.2}
  {The system shall save a record of every finished session to the user's account.}
  {UR-18}
  {When a session ends, a record with its start time, duration and services used is saved to the user's account.}
  {Must}
\acnext{Given the device is offline when a session ends, then the record is stored on the device and uploaded when the connection returns.}
\acend{After signing in on another device, the saved records are available.}

\frfirst{FR 7.3}
  {The system shall calculate and display the user's current streak.}
  {UR-17}
  {The current streak counts consecutive days with at least one completed session.}
  {Must}
\acnext{The streak is shown on the Home Space and on the History screen.}
\acend{A day without a completed session resets the streak to zero.}

\frfirst{FR 7.4}
  {The system shall display a history of the user's past sessions.}
  {UR-18}
  {The History screen lists past sessions from newest to oldest, each with its date, duration and services used.}
  {Must}
\acnext{When there are no sessions, an empty-state message is shown.}
\acend{If the history cannot be loaded, an error message with a retry option is shown.}

\frfirst{FR 7.5}
  {The system shall allow the user to turn the one-minute notice on or off.}
  {UR-19}
  {Settings contains a switch for the one-minute notice, turned on by default.}
  {Should}
\acnext{When the switch is off, no one-minute notice is shown during sessions.}
\acend{The setting is kept after the app is restarted.}

\frfirst{FR 7.6}
  {The system shall show where the news, music and video content comes from.}
  {UR-19}
  {Settings contains a Content credits entry.}
  {Should}
\acend{The entry lists the source of the news, music and video content used in the app.}

\frfirst{FR 7.7}
  {The system shall show a loading state while content is being loaded.}
  {UR-20}
  {While news, music or video content is loading, a placeholder or loading indicator is shown instead of a blank screen.}
  {Should}
\acend{The loading indicator disappears when the content is displayed or an error is shown.}

\frfirst{FR 7.8}
  {The system shall show offline and error states with a retry option.}
  {UR-20}
  {When a content request fails because there is no connection, an offline message with a retry option is shown.}
  {Should}
\acnext{When the user selects retry and the connection is available, the content loads.}
\acend{The session countdown continues while an offline or error message is displayed.}
